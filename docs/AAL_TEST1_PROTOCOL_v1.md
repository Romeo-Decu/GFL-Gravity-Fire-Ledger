# AAL test 1 protocol (pre-registered)

**Registered:** 2026-11-11, before any analyst received data and before GFL's estimator ran on the synthetic set · **Author:** Claude (PM) · **Owner approval:** 2026-11-11 (plan of the day, DEC-052) · **Code frozen at:** commit `ea984bd` for `tools/b6_window_rule.py` (R-W2), plus the commit that seals this file for the synthetic tools.

The test has two parts under one protocol. Part S has a known answer and measures the analysts, including GFL's own estimator. Part B11 has no known answer and tests a prediction registered on 2026-11-10 (DEC-047).

## Part S: synthetic profiles with a known front speed

**Data.** Two cases, S1 and S2, generated by `tools/synth_flame_profiles.py` in the format of the blind B6 package (band profiles, frame times and exposures, flow-display schedule). The model is stated in the tool's header. S1 has a leading edge of constant width; S2 has a leading edge that sharpens over time, as observed in B6 (RES-008). Both include an ignition flash, auto-exposure changes, one deliberately over-exposed (clipped) frame, a long gap before two post-burn frames, and four flow-display changes. The front speed differs between flow settings.

**Truth.** The truth file (speeds, seed, shape parameters) stays outside the repository until scoring; its SHA-256 is sealed in the ledger with this protocol. The truth is the speed of the generator's front position, defined as the leading-edge half-maximum point, during the air-display-3 interval. This definition is a modelling choice and is stated to every analyst after scoring; under it, a threshold low on the leading ramp is biased when the edge sharpens (S2), and that bias is part of what the test measures.

**Who knows what.** Claude generated the data and knows the truth, so Claude is not an analyst in part S. Claude runs only GFL's frozen estimator (`tools/synthetic_front_check.py`, a mechanical adapter that changes no rule parameter) and the scoring. Analysts receive only the package and the task text (`TASK_SYNTHETIC.md`).

**Analysts.** Through AAL: kimi26, deepseek_v4, grok47, gpt55 and Mistral Large 3 (allowed to show whether it improves). Outside AAL, if the owner chooses: Manus, from the owner's account (it executes its own code), recorded in the disclosure. GFL's estimator is scored with the same metrics.

**Estimand asked.** For each case: the front speed (mm/s) during the air-display-3 interval, a 95 % interval, the front definition used, and the code.

**Metrics (fixed now).**
| Code | Metric | Pass |
|---|---|---|
| M1 | Relative error of the preferred value, per case: abs(v − v_true) / v_true | ≤ 5 % good, ≤ 10 % acceptable, > 10 % fail |
| M2 | Interval coverage: the stated 95 % interval contains v_true | yes / no, per case |
| M3 | Reproducibility: the delivered code, re-executed by GFL (`python -I`, empty environment, numpy and pandas only), produces the reported numbers within 0.5 % | yes / no |
| M4 | Constraint compliance: numpy and pandas only; nothing read except the package | yes / no |
| M5 | Honest labelling: every number labelled; no number claimed as computed that the code does not produce | count of violations; any fabricated number fails |
| M6 | Direction of propagation stated correctly | yes / no |

**Role assignment rule (fixed now).** A model is eligible as **blind analyst** if M3, M4 and M6 pass, M5 has no fabrication, and M1 ≤ 10 % on S1. It is eligible as **auditor** only if, in addition, it reported every anomaly planted in the data that affects the estimand (clipped frame, flash, gap, flow changes) or explicitly marked one as not examined. **Red team** is assigned from WF-0011 history and from the quality of objections in this test, judged against the truth after scoring. Results and roles are recorded in the register whatever they are, including GFL's own.

## Part B11: the registered prediction

**Prediction (DEC-047, sealed and timestamped 2026-11-10 before acquisition).** B11 (200 µm PMMA film, 20 mm, flow restrictor 2, 21 % O₂) at air display 3: leading-edge rate 0.85–1.15 mm/s under R-W2 with the reference definition (0.1 of each frame's peak).

**Procedure.** Acquire the B11 files from NASA PSI-25 and seal them as received; transcribe the air-display overlay from the original video at the same sampling as B6; run `tools/b6_window_rule.py select --rule R-W2` and `fit`, unchanged. A red team chosen from part S reviews the run. Validation is deterministic re-execution.

**Outcomes, all reported.** Inside the band: inverse-thickness scaling supported for this pair at this flow. Outside: not supported. No air-display-3 segment passing the gates: test not possible, never counted as passed. The part S result for GFL's estimator on S2 is reported next to B11, because it says how far the reference definition can be biased by a sharpening edge.

## What does not change during the test

The window rule, the estimators, the prediction band, the metrics and the role rule. AAL is used as it is (defects ISS-041 known). Any deviation is recorded as a deviation, not absorbed.

## Amendment A1 (2026-11-11, before any analyst received data)

1. **Part S runs as a direct capability probe, not inside an AAL workflow.** The GFL project in AAL assigns Reality_Analyst only to deepseek_v4 and kimi26, and AAL packets differ by phase (ISS-041 #9), so a fair comparison needs one identical prompt per model. `tools/capability_probe.py` sends the same task (`data/synthetic/aal_test1/TASK_FOR_API_ANALYSTS.md` with `DATA_SCHEMA_AND_SAMPLE.md`) to every Foundry deployment (gpt-5.5, gpt-6-astra, grok-4.7, Kimi-K2.6, Mistral-Large-3, DeepSeek-V4-Pro, Decision-1), with no history, from the owner's machine. Manus, if used, gets the full package (`TASK_SYNTHETIC.md`) and runs its own code.
2. **M3 for models that cannot run code:** the delivered script runs on the full files without error and prints the `RESULT` lines; M1, M2 and M6 are scored on those printed values. A number in the report that the script does not print counts under M5.
3. **AAL is used for part B11** (semi-autonomous workflow on the GFL project), with roles taken from part S scores where the AAL configuration allows; any configuration change is the owner's and is recorded.
