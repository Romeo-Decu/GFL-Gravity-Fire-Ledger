# GFL map: where we started, what we built, what is missing (2026-11-11)

**Purpose:** the input for Thursday's decisions (DEC-052) and for the independent evaluation. **Author:** Claude (PM). **Baseline:** the Release A scope (`docs/RELEASE_A_SCOPE_AND_ACCEPTANCE_v1.0.md`, DEC-014…018, 4 Nov), which set a maturity target per module: V = implemented and validated on NASA data, P = bounded prototype, D = documented specification. Status words below: **met**, **partly met**, **not met**, with the evidence.

## 1. How the architecture moved

| Date | Architecture | Why it changed |
|---|---|---|
| 1–3 Nov | Concept: a physics-aware evidence platform with three separate questions (relevance, comparability, transferability) and a canonical evidence graph; first demonstration case B3 (owner docs 0–3, 10) | Founding idea |
| 3–4 Nov | Competitor review (Fotia, MicroFire Atlas): a broad catalogue and dashboard are not a differentiator; GFL competes on rigour, not breadth (DEC-04 in doc 5) | Landscape |
| 4 Nov | Release A scope: integrity and deviation layer as minimum success (DEC-018); 100-µm PMMA family as anchor (DEC-016) | Scope |
| 5 Nov | Zero-trust ledger (signed, hash-chained, two keys), Evidence Vault tiers; B3 dropped as measured case (its link to 2.2 mm/s never established), B6 becomes the measured case | Integrity first; B3 evidence insufficient |
| 6–9 Nov | Blind independent analyses through AAL (WF-0011); re-execution by GFL; failures kept as records | Independent check of the measurement |
| 10 Nov | Window rule fixed before fitting; corrected headline; cold review; AI layer (ranked AI findings, citation check, second model), comparable-run ranking, MCP server, INDUS relevance; repository renamed | Review findings; the challenge asks for AI summary and ranking |
| 11 Nov | Ground-truth test of every model and of GFL's own estimator; B11 prediction test | First test with a known answer |
